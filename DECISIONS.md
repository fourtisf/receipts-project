## M1 — contracts

- **D-011 Vault reads its configuration from the factory.** `ReceiptsVault(owner, maxSlippageBps, dailyLimitUsd, drawdownBps)` reads router / registry / base / treasury / protocol cut / beta cap / token list from `msg.sender` (the factory). A vault can only ever hold the factory's fixed list, and Blockscout verification needs only 4 constructor args.
- **D-012 NAV and prices never revert internally.** `_nav` / `_readPrice` return a status (try/catch on feeds, low-level `balanceOf`), so `withdraw` cannot be bricked by any feed or token; the external views `navStrict()` / `navLenient()` / `priceUsd()` revert with the precise error (`StaleOraclePrice(token)` / `BadOraclePrice(token)`).
- **D-013 Feed `decimals()` is read live**, not cached, at the cost of one extra call per held token (safety over gas).
- **D-014 Lenient staleness = `max(token.maxStaleness, 7 days)`.**
- **D-015 Base token (USDG) cannot be disabled**; every other listed token can. *Revised after the independent review (F-2):* while following, a held token cannot be disabled (`TokenHeld`) — withdraw it instead, which settles fees first; enabling adds the value like a deposit. Not following: disable/enable scale/raise the marks like a withdrawal/deposit.
- **D-016 Fees use `min(creatorShareSnapshot, current share)`.** Creators can only lower shares, so followers automatically benefit from a lowered share without re-following. Still within invariant 10.
- **D-017 Withdraw updates marks before the transfer** (predicted `navAfter = navBefore − value(withdrawn)`), i.e. checks-effects-interactions, instead of measuring NAV after the transfer.
- **D-018 `follow` while marks are frozen re-arms them** (`peak = hwm = navStrict`, emits `MarksReset`); `unfollow` / `follow` skip fee settlement while frozen (fees accrued before the freeze are forgone, documented).
- **D-019 `resetMarks` also restarts the fee period** (`lastFeeSettle = now`).
- **D-020 Extra errors beyond the interface:** `StrategyInactive(id)`, `MarksAreFrozen()`, `SameToken()`, `BadConfig()`, `OnlySelf()` (vault) and `BadConfig(string)` (factory). The interface has no error for these cases; functions match the interfaces exactly.
- **D-021 Extra public members:** `settleFeesForWithdraw()` (self-call only, needed for best-effort settlement inside `withdraw`), `tokenConfig(token)`, `windowStart()`, `usedInWindowUsd()` and constants (UI meters).
- **D-022 `executeSignal` rejects dust** (`ZeroAmount`) when the oracle minimum output rounds to 0 — found by the invariant suite (a 1-wei USDG buy of WBTC would otherwise succeed with 0 output).
- **D-023 Breaker trip emits `PausedChanged(true)` and `BreakerTripped`** so the indexer tracks `paused` from one event type.
- **D-024 `checkBreaker()` returns true while breached** (even if already paused) but only emits once.
- **D-025 ArbSys stipend 30k gas** (fallback to `block.number` on anvil / chains without the precompile).
- **D-026 Reentrancy guard on every state-changing vault function**, owner setters included (removes Slither's cross-function reentrancy class entirely). `ReentrancyGuard` (storage), not the transient variant, for maximum chain compatibility.
- **D-027 `VaultFactory` uses plain `new`** (no CREATE2 / clones / proxies). Factory admin can set the default operator to `address(0)` (new vaults start without a bot).
- **D-028 Fork tests read `config/robinhood.json` directly** and fund the test owner by impersonating the deepest USDG pool (no storage hacks on the Paxos proxy).
- **D-029 Deployment output:** `deployments/<chainId>.json`, or `deployments/fork.json` with `DEPLOYMENT_NAME=fork` (anvil forks also report chain 4663).
- **D-030 Public dRPC is rate-limited (HTTP 429):** develop against a local anvil fork pinned to a block (anvil caches state); use a paid RPC key for production and CI fork tests.

## M2 — indexer + read API

- **D-031 `Commit.hash` is not unique** (index only). Anyone can register a strategy and commit a copy of another commit's hash; a unique constraint would let that stall the indexer forever. Identity is `(strategyId, nonce)`; `GET /receipts/<hash>` returns the earliest receipt with that hash.
- **D-032 Schema additions (migration `m2_reorg_metadata`)**: `Commit.revealBlock`, `Commit.missedBlock`, `Strategy.registeredBlock`, `Vault.createdBlock` for exact reorg rollback; `MetadataDoc` (content-addressed strategy metadata).
- **D-033 Strategy metadata is content-addressed**: `metadataURI = https://APP_DOMAIN/api/metadata/<keccak256(canonical JSON)>`. The on-chain URI pins the exact metadata and anyone can recompute the hash. Foreign URIs get neutral defaults ("Unnamed strategy", template `external`).
- **D-034 Labels are never self-declared**: `AI` only when the strategy committed a non-zero `modelHash`; `HOUSE` only when the creator is in `HOUSE_CREATORS`.
- **D-035 Vault logs are fetched by topic** (all `ReceiptsVault` event signatures) and filtered by known vault addresses, so indexing scales to any number of vaults; vaults created in a batch are known for their own constructor events in the same batch.
- **D-036 Canonical state from chain reads**: after each batch the indexer re-reads touched strategies (`strategyOf`) and vaults (getters + `navLenient`), instead of re-deriving state from events. Counters (`commitCount`, `revealCount`, `missedCount`) come from the registry itself.
- **D-037 Reorg handling**: on a hash mismatch at the cursor, roll back `REORG_REWIND` (64) blocks: delete executions / vault events / commits above the fork, undo reveals and missed marks above it, then refresh survivors from chain and re-index.
- **D-038 Match check**: pair and direction must equal the revealed signal; buys may not exceed `sizeBps × allocation` + 2%. Under-sizing is accepted with a note (the executor clamps to daily limit, balance and allocation headroom). Sells are checked for pair/direction only.
- **D-039 Equity model** (`apps/worker/src/stats/equity.ts`, documented in code): revealed signals applied at commit time, real volume-weighted vault fills when available ("live") otherwise the Chainlink price at the commit block plus 0.1% cost ("paper"); hourly marks from indexed Chainlink rounds; hold = equal-weight buy-and-hold. Missed commits never trade.
- **D-040 Token decimals added to `config/robinhood.json`** (verified on-chain; re-checked by the fork test and `scripts/check-config.ts`).
- **D-041 Fill price and oracle price on receipts** (`fillPriceUsd`, `oraclePriceUsd`, `slippageBps`) to render the prototype's receipt lines.
- **D-042 Tests use a fresh Postgres schema per file** (`@receipts/db/testing`, non-destructive `migrate deploy`, dropped afterwards); `prisma migrate reset` is never used by tooling.

## M3 — web (read-only)

- **D-060 Server components fetch the API directly** (`API_INTERNAL_URL`), client components call `/api/*`; every response is parsed with the shared zod schemas. Landing uses ISR (`revalidate = 10`), app pages render on demand.
- **D-061 Fonts via `next/font/local`** from the npm fontsource / geist files (preloaded, no layout shift, no Google Fonts at build time).
- **D-062 Webpack `IgnorePlugin` for optional wallet-SDK peers** (`@x402/*`, `@react-native-async-storage/async-storage`) that are referenced but never executed in the browser build.
- **D-063 Prototype colours kept as designed** even where Lighthouse flags the `faint` grey contrast (96 accessibility); changing the palette is a design decision for the owner.
- **D-064 Optional links come from env** (`NEXT_PUBLIC_DOCS_URL`, social / verify links); without them the nav "Docs" points to "How it works".
- **D-065 API proxy trust = `loopback`** (only the local Nginx hop) so `X-Forwarded-For` cannot be spoofed; direct loopback requests without that header (Next.js SSR) are exempt from the per-IP rate limit.

## M4 — web writes (API side)

- **D-043 SIWE via `viem/siwe`** (no `siwe`/ethers dependency). Nonce single-use and 10-minute expiry, claimed atomically (`updateMany … usedAt: null`). Domain must equal `APP_DOMAIN`, chain 4663, URI `https://APP_DOMAIN` (`http://localhost…` only outside production). EOA signatures verified locally; EIP-1271 smart wallets via an on-chain check. Session cookie `sid`: httpOnly, SameSite=Lax, Secure in production, signed with `SESSION_SECRET`, 7 days.
- **D-044 `PATCH /strategies/:id` returns a `setMetadataURI` transaction** instead of editing the DB: metadata is content-addressed and pinned on-chain, so renaming creates a new document and the creator signs the URI change (the indexer applies it). `POST /strategies/:id/deactivate` returns `setActive(false)` tx data. The API never sends transactions.
- **D-045 No backtests for AI templates** (`NO_AI_BACKTEST`): a model run today would see today's news, so an AI "backtest" would be fiction. AI strategies build a live record from their first commit.
- **D-046 Backtest candles**: Coinbase (fallback Binance) for crypto, Polygon/Alpaca for stocks when `MARKET_DATA_API_KEY` is set, else hourly candles from indexed Chainlink rounds. Cached 10 min per input hash in Redis.
- **D-047 Writes rate-limited to 20/min** per IP (reads 120/min), shared across API instances through Redis.

## M5 — worker pipeline

- **D-048 Encrypted salt + signal are stored before the commit transaction is sent** (AES-256-GCM, `SALT_ENCRYPTION_KEY`), so any crash between commit and reveal is recoverable: on start and every minute `recoverPending()` reveals open commits; secrets of commits that never landed are dropped (the nonce is reused).
- **D-049 Local `hashSignal` must equal `SignalRegistry.hashSignal`** (view) before every commit, or the worker refuses to commit.
- **D-050 Sizing**: BUY spends `sizeBps × allocation`, clamped to allocation headroom (`allocation − exposure`), 99.9% of `remainingDailyUsd()` and the USDG balance; SELL sells `sizeBps` of the holding, clamped to the remaining daily limit. Matches the indexer's match check (D-038).
- **D-051 Quotes by simulation** (D-010): `eth_call executeSignal(minOut = 0)` from the executor → `minOutFromOperator = simulated × (1 − 0.5%)`; the contract still enforces the oracle minimum. A simulated `0` (breaker would trip) or any revert skips the vault with the decoded reason in the log.
- **D-052 One executor queue, concurrency 1**: signals run strictly one after another (nonces and reveals stay ordered). Per-key Redis locks guard against an accidental second worker. Executions for many vaults are sent back-to-back (viem nonce manager) and awaited together, so one vault never blocks the others.
- **D-053 Stuck transactions**: Robinhood Chain (Arbitrum Orbit) has a first-come-first-served sequencer without a priority-fee auction, so the pipeline retries failed sends with backoff instead of gas-bumping replacements; reveal retries continue until the deadline and raise a critical alert 10 min before it.
- **D-054 Runner state is public**: the paper portfolio a template decides on is rebuilt from the strategy's revealed signals at commit-time Chainlink prices (the same data anyone can read); no hidden state. A strategy with an unrevealed own commit is not evaluated. One evaluation per strategy per hour (Redis key), stocks only during NYSE hours (America/New_York).
- **D-055 AI runner refuses to trade if `AI_MODEL` ≠ the committed `modelHash`**; temperature 0, strict JSON answer; prompt + inputs + output are stored and published at reveal (`AiArtifact.publishedAt`), never before.
- **D-056 `markMissed` for every expired commit** (any strategy) every 5 min, paid by the executor key.
- **D-057 Alerts** are rows in `AlertLog` (`sentAt` added) delivered to Telegram every 30 s; health checks every 5 min (gas < `MIN_GAS_BALANCE_ETH`, indexer lag > 2 min, tx failure rate > 10% in 15 min) with Redis de-duplication.
- **D-058 House strategies** are registered by `scripts/register-house.ts` (dry run by default, `--broadcast` sends): Mag7 Rebalance (rebalance, 7 stocks, weekly, 2% drift, 10% share), SPY/QQQ Rotation (20-day, Friday close, 10%), News Desk (AI, NVDA/TSLA/COIN, 20%, modelHash = keccak256(AI_MODEL)).
- **D-059 Soak on the fork is compressed** (`scripts/soak-fork.ts`, minutes not 48 h, with a forced crash between commit and reveal). The 48 h soak in the launch checklist must run against the deployed stack.

## Post-review hardening (independent adversarial review)

- **D-066 NAV is overflow-safe and gas-capped** (F-1, F-5): values via `Math.tryMul`, any value or NAV above 2^128 is a bad read; feed and `balanceOf` reads are low-level static calls with gas caps (200k / 100k) and no ABI validation that could throw; decimals > 36 rejected at vault creation.
- **D-067 `follow` / `unfollow` revert `FeeUnpaid`** when a due fee cannot be paid in USDG (F-3); `settleFees` / `withdraw` keep deferring.
- **D-068 Accepted and documented**: dead-feed dust griefing (F-4, owner recovery tested), push-payment fees vs a frozen creator (F-7), "withdraw max" must leave room for a pending fee (F-6, handled in the UI), stock-feed gaps can exceed the 0.5% lag assumption.

## M4 — web writes (web side)

- **D-069 `GET /auth/nonce` also returns `{ domain, uri }`** — the exact values `/auth/verify` checks — so the browser never builds a SIWE message the API will reject. **`GET /auth/session`** answers 200 with `{ address | null }` (no 401 console noise on every page).
- **D-070 Browser chain reads batch through Multicall3** (deployed on Robinhood Chain at the canonical address).
- **D-071 Client-side verification only counts `Executed` logs from genuine vaults** (`factory.vaultOf(vault.owner()) == vault`); the oracle-price check is shown "from API" because recomputing a past Chainlink price needs an archive node.
- **D-072 "Withdraw max" of USDG keeps back the pending creator fee** (review F-6); held tokens are locked in the asset chips while following (F-2); `FeeUnpaid` / `TokenHeld` decoded with amounts.
- **D-073 Web fork e2e runs on its own anvil (:8546)** and prefetches state inside an `evm_snapshot` because the free RPC prunes state within minutes.
